SR110 Multi-File Documentation Structure

Overview

The documentation has been split into 3 files to support CPU-specific enum definitions while maintaining a unified documentation tree structure.

File Structure

1. sr110_groups.h (Main Group Definitions)

  • Defines the Doxygen group hierarchy
  • Contains: SR110 → CM55 → Peripheral categories (UART, GPIO, PINMUX, CLK, SPI, SDIO, I2C)
  • No typedef definitions - only documentation groups

2. sr110_cm55.h (CM55-Specific Definitions)

  • Contains all typedef enums for CM55
  • Uses \ingroup to link to groups in sr110_groups.h
  • Example: uart_instance_en with 3 instances (UART0, UART1, UARTLP=2)

How It Works

  1. Doxygen processes all 3 files (configured in DoxyFile INPUT field)
  2. Group hierarchy is established by sr110_groups.h
  3. CM55 definitions are placed into CM55 groups via \ingroup tags
  4. Result: Navigation tree shows SR110 → CM55-specific enum values

Key Benefits

✅ Same typedef name (uart_instance_en) in both files
✅ CM55-specific values (e.g., UARTs: 3)
✅ Unified documentation tree (SR110 → CM55)
✅ No compilation - documentation only
✅ Clean separation - easy to maintain per-CPU differences
